# GPTBot got a 429 even though robots.txt allowed it

Our robots.txt allowed GPTBot. Our web host answered it with HTTP 429 anyway.

Other AI crawlers hit the same site, under the same robots.txt, in September 2026. They got through.

The only difference was the user agent. The host blocked GPTBot/1* at the edge, before the request reached the site.

A 429 normally means "too many requests", so it reads like ordinary rate limiting and is easy to wave off. In our case the rule was keyed to the user agent string.

We had treated robots.txt as the switch that decides who gets in. Really it's a request that well-behaved crawlers choose to follow. A host, CDN or firewall rule can turn a bot away before that file even comes into play. Meanwhile a robots.txt checker still reports the bot as allowed, because the file itself is fine.

If you've told a client their site is open to AI crawlers because robots.txt says so, that may not be true.

The check:

1. Pull a week of server or CDN logs and filter for the GPTBot user agent. If a CDN sits in front of the site, include its logs, since the edge can answer before the origin server sees the request.
2. Count the status codes. We saw 429s for GPTBot while other AI crawlers got through. Put the crawlers side by side, because the comparison is what tells you the block is aimed at one bot.
3. Open the host's bot and firewall settings and read them alongside robots.txt. Look for rules that match on user agent, including wildcard patterns like GPTBot/1*.

If the logs and robots.txt disagree, believe the logs. They record what actually happened.

Flowra's AI traffic tracking reads ChatGPT and Perplexity referrals from GA4, so it sees visits that arrive. It can't see crawls that were refused. Those only show up in server logs.

When did you last check what your host actually returns to GPTBot, as opposed to what robots.txt allows?

For an nginx or Apache access log in the default combined format, this counts the status codes GPTBot received:

grep "GPTBot" access.log | awk '{print $9}' | sort | uniq -c
