# Refresh old posts without losing rankings: map queries first

A blog post that has lost 20% of its clicks usually gets one of two fixes. Both can cost it the rankings it still has.

The full rewrite cuts or rewords the sections that still answer real queries, and those queries leave with them.

A fresh publish date alone won't help. Google's helpful content guidance flags changing dates to seem fresh when the content hasn't substantially changed.

Both fail for the same reason: nobody checked what the page already wins.

So start in Search Console, before a word changes:

1. Filter to the page, export the Queries tab, save the old version and note clicks, impressions, CTR and position. That export is your baseline. If the post belongs to an agency client, it is also what you show them when they ask what changed.

2. Sort the export by impressions. For each query with meaningful impressions, find the section that answers it. Write the query next to that heading so whoever edits the post can see what not to break.

3. Those sections keep their heading wording and core answer. Improve around them. Delete a section only after confirming it ranks for nothing.

4. Show "Last updated" only after a substantial change, and keep the original publish date. The label tells readers something changed, so make sure something did.

Then request a recrawl and ignore the first two weeks or so. If the page is still down on its old queries three to four weeks later and the rest of the site isn't, restore the section you cut before rolling back the whole page.

Restoring one section keeps the rest of your changes in place. Rolling back the page throws out the good edits along with the mistake.
