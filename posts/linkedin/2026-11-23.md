# Before you block all of AWS, test the crawlers you want

26,429 requests in 34 hours, all from one AWS address.

That is the crawler Open3DLab found in its logs in October. It said it was from Roblox and ignored both robots.txt and the sites' terms. By the end it had taken 145.5 GB of creators' 3D files.

Under the story, the popular reply is: just block all of AWS. Block every big cloud provider and be done with it.

We get the anger. But a network-wide block is as blunt as the scraper, and nobody in those replies is asking which bots it shuts out along with it.

We ran into the opposite problem in September. We saw a web host answering GPTBot with HTTP 429 at the edge, even though robots.txt allowed it and other AI crawlers got through. The site said yes in robots.txt, and the host said no before the request ever reached it.

That kind of block is easy to miss, because nothing in your own files changes. Robots.txt still says yes, and the site looks normal when you open it.

So before you switch on a blanket block:

1. List the crawlers you want, search and AI, and check how the block treats them.

2. After the change, look for their hits in your server or CDN logs and test with each user agent. You want a 200, not a 403 or 429.

3. Watch AI referral visits from ChatGPT and Perplexity in GA4 for the following weeks and compare them with the weeks before.

If you run sites for clients, the block may sit with a host or CDN you don't control. Ask them which rules apply to bots, then check the result yourself with step 2.

Which crawler would you test first before blocking a cloud range?
