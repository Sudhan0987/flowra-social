# GPTBot got a 429 while robots.txt allowed it

429. That is the status code GPTBot got from our web host in September 2026, while our robots.txt allowed it.

Other AI crawlers came through on the same site, under the same rules. The block sat at the host's edge and only matched one user agent.

Nothing in a browser would have shown it. Pages loaded fine for people, us included, and robots.txt said allow.

robots.txt is a file that crawlers read and choose to respect. It has no say over what your host or CDN does before a request ever reaches your site.

A 429 means "Too Many Requests". It is a rate-limit response, so a crawler reads it as "come back later", and nothing about it looks broken from the outside.

Our view: if you only check robots.txt, you are checking what you meant to allow. The status code tells you what each crawler actually got.

The carousel walks through the comparison and the check we run now: request a few key URLs as each AI crawler you allow, and read the status code that comes back.

**The check, in short:**

1. Pick a handful of URLs that matter to you: the homepage, a top article, a key product or service page.
2. Request each one with a normal browser user agent first, so you have a baseline.
3. Then request the same URLs as each AI crawler you allow in robots.txt.
4. Write down the status code for every pair. A 200 for people next to a 403 or 429 for one bot is the pattern you are looking for.
5. If one crawler gets a different answer, go to the bot and rate-limit settings at your host or CDN. Editing robots.txt will not fix it.

A spoofed user agent has one limit. The request comes from your IP, not the crawler's, and some hosts check IP ranges too. Your server logs have the final word on what the real GPTBot received.
